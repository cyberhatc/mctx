# Security Policy

## Supported Versions

Only version 2.1.5 and select recent minor releases are actively supported with security updates.

| Version | Supported          |
| ------- | ------------------ |
| 2.1.x   | :white_check_mark: |
| 2.0.x   | :x:                |
| 1.x.x   | :x:                |

## Reporting a Vulnerability

We take the security of this project seriously. If you discover a security vulnerability, please follow these steps to report it responsibly:

### 1. How to Submit a Report
* **Private Vulnerability Reporting (Recommended):** Use the **"Report a vulnerability"** button under the **Security** tab in this GitHub repository to open a private advisory.
* **Email:** If private reporting is unavailable, email security reports to `security@yourdomain.com`. **Please do not open a public issue.**

### 2. What to Include
To help us evaluate and fix the issue quickly, please include:
* A detailed description of the vulnerability.
* Clear, step-by-step instructions (or a proof-of-concept) to reproduce it.
* The potential impact of the exploit.

### 3. Response & Resolution Process
* **Acknowledgment:** You will receive an initial response acknowledging your report within **48 hours**.
* **Status Updates:** We will provide updates on the triage and fix process every **3–5 business days**.
* **Fix & Release:** If accepted, a patch will be prepared and released in a patch update (e.g., `2.1.6`).
* **Public Disclosure:** Once the fix is released, a public security advisory will be published crediting you for the discovery (unless you prefer to remain anonymous).
